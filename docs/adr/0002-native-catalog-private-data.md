## Контекст

Менеджеру требовалось редактировать каталог в OpenCart. Для переноса были нужны стабильные идентификаторы источника, отдельные статусы цены и наличия, прежние адреса и контроль доступа к вложениям.

## Решение

MySQL хранит товары, категории, производителей и характеристики в штатных сущностях OpenCart. Таблицы расширения дополняют их метаданными переноса, контентом, связями и правилами выдачи файлов. Сами файлы хранятся вне публичного каталога сайта. Витрина применяет единые правила публикации в выдаче, поиске и sitemap. Выдача вложения требует отдельного разрешения для этого файла.

## Почему

Самостоятельная витрина с отдельной копией каталога дала бы больше свободы при моделировании, но потребовала бы синхронизировать правки из админки и правила видимости между двумя системами. Штатные сущности дают один источник для каталога. Таблицы расширения сохраняют сведения, для которых штатных полей недостаточно.

## Последствия

Импорт и миграции должны согласованно обновлять штатные данные и данные расширения, сохраняя связь с источником. Для массового снятия с публикации импорт требует отдельного режима и предпросмотра. Для восстановления нужны копии MySQL и приватных файлов.
