# Установка СМ ТЕХНО

Дистрибутив содержит официальный OpenCart 4.1.0.4 без изменений и расширение
`cmteh.ocmod.zip`. Для локальной сборки нужен Python 3.10 или новее и официальный
архив с контрольной суммой из `open-cart.lock.json`.

```text
python opencart/packaging/build.py --upstream /path/opencart-4.1.0.4.zip --output /private/release
```

1. Сверьте SHA-256 кандидата и архива ядра. Подготовьте закрытый HTTPS хост,
   пустую БД MySQL, каталог под сайт и закрытый каталог вне web root на той же
   файловой системе. Держите установщик закрытым внешним ограничением доступа.
2. Из официального архива перенесите содержимое `upload/` в web root. Создайте
   `config.php` и `admin/config.php` из шаблонов OpenCart. Пройдите штатный
   установщик с отдельной БД и настройками владельца. PHP веба и CLI должны
   иметь mysqli, pdo_mysql, GD, cURL, zip, zlib, openssl, mbstring и DOM/XML.
3. Сохраняя внешнее ограничение доступа, выполните `php setup/seal.php WEB_ROOT
   PRIVATE_DIR` от владельца файлов сайта. Это размещает конфиги и OpenCart
   storage в приватном каталоге и добавляет правила Apache. Обеспечьте чтение
   приватных конфигов только системному пользователю приложения и владельцу.
   На PHP-FPM проверьте `open_basedir` и чтение приватного каталога PHP.
   Если есть собственные директивы `.htaccess` для PHP/HTTPS, согласуйте их
   объединение с правилами пакета до включения доступа. Проверьте rewrite,
   запрет прямого доступа к конфигам, инсталлятору и PHP файлам расширения.
   Сохраните `AddType application/javascript .mjs`: некоторые хостинги не
   назначают MIME тип модулям автоматически. На целевом HTTPS хосте проверьте
   Content-Type файлов `storefront.mjs`, `request.mjs`, `request-import.mjs`
   и `cart.mjs`, затем реальный клик «В корзину», добавление списка и reload.
   HTTP 200 самого файла не доказывает, что браузер запускает модуль.
   При смене версии клиентских модулей обновляйте `v` в layout и во всех
   их статических import вместе. Смена только адреса входного скрипта
   оставляет старые зависимости в кеше; общая корзина должна загружаться
   из одного и того же URL во всей цепочке. XLSX reader наследует эту версию.
4. В админке загрузите `cmteh.ocmod.zip` в Extensions → Installer и нажмите
   Install для пакета. Затем Extensions → Extensions → Modules → СМ ТЕХНО →
   Install. Убедитесь, что витрина и админка работают до открытия доступа.
5. Для обновления сохраните БД и файлы, закройте публичную витрину, замените
   файлы **только** расширения из нового проверенного архива, сохранив права.
   Выполните «Применить миграции» на странице модуля в админке, проверьте
   версию, витрину и заявки. Операция не переустанавливает БД. Для отката
   требуется отдельное проверенное восстановление с учётом новых заявок.
   Правки `setup/htaccess` переносятся отдельно с сохранением действующих
   ограничений доступа; обновление ZIP расширения не меняет корневой `.htaccess`.

Распакованный релиз, исходные импорты, резервные копии и CLI держите вне
web root. Отдельно сохраните cron, настройки панели и способ восстановления.
Отчёт по реальному хостингу требует проверок на выбранном аккаунте.
# Отдельная почта расценок

Установочный архив также содержит `cli/send-quotes.php`; используйте именно
байты из проверенного архива. Private `quote-mail.json`, ограничения, отдельный
cron, local capture и безопасный откат описаны в поставляемом `README.md`.
Новый worker запускается явно с `--hosting`; существующий `send-leads.php`
для расценок не включать. При откате остановить только quote cron и сохранить
новые quote-таблицы и BLOB без отката данных.
