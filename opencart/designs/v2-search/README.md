# V2 — поисковая версия

Локальный презентационный вариант существующего OpenCart-приложения СМ ТЕХНО. V1 — текущий сайт https://test.cmteh.ru/, V2 — это оформление с поиском в центре. В этом прогоне V1 не обновляется.

**Админка и бизнес-система остаются одними.** V2 использует те же view models, каталог, складские предложения, корзину и обработку списка/файла. Здесь нет новых admin controllers, редакторов, схем или дублирования бизнес-логики. Сначала владелец смотрит V2 и выбирает оформление; подключение выбранного варианта к существующей админке/реальным данным — отдельный согласованный шаг. Native OpenCart в disposable local runtime является тестовой инфраструктурой существующего приложения, а не второй админкой, которую нужно вести.

## Запуск на этом компьютере

Общая база синхронизирована с принятым `origin/main` `8a5ada0` (PR26). V2 читает те же проверенные сервером поля analytics/verification, что default layout: два verification meta и условный локальный загрузчик `analytics.js`. Собственных настроек или валидации нет. В этом preview счётчики выключены; синтетическая HTTP-проверка временно задаёт тестовые значения через существующий CMS model и точно восстанавливает запись, не исполняя скрипты и не обращаясь к провайдерам. Подключения к реальной админке V1 нет.

Из `D:/codex/CMTEH.RU/V2-search`:

```text
python opencart/dev/v2-local.py --runtime-dir D:/codex/temp/cmteh-v2-search-20261112 --port 3162 --upstream D:/codex/temp/cmteh-opencart-cache/opencart-4.1.0.4.zip start
```

После успешного старта: http://127.0.0.1:3162/ . MySQL не публикуется на хост; runtime имеет собственные Compose project, volumes, private storage и одноразовые локальные credentials. Не копируйте сюда боевые секреты, клиентские заявки или медиа V1. Данные, цены и контакты в этом preview синтетические из `fixtures/demo.ndjson`; два предложения тестовых складов добавлены существующей loopback fixture. SMTP/cron и внешние уведомления не запускаются.

Повторный `start` обновляет установленный extension и presentation overlay, но не очищает и не переимпортирует уже созданный каталог. Изменённый demo fixture требует нового runtime. Путь и порт защищены ownership marker, launcher отвергает V1 checkout, собственный checkout, symlink/junction и чужой непустой каталог.

Если Docker сообщает об исчерпании стандартных address pools, не удаляйте чужие сети. После проверки существующих Docker-сетей и маршрутов задайте штатный `CMTEH_DOCKER_SUBNET` со свободной приватной /28 при первом запуске. Существующий runtime сохраняет её в `network.json`. Для данного экземпляра использована `10.231.93.0/28`; для другой чистой копии нужна другая свободная подсеть. Повторный запуск текущего экземпляра не требует переменной.

Для применения только новых Twig/CSS/JS/изображений без миграций и импорта:

```text
python opencart/dev/v2-local.py --runtime-dir D:/codex/temp/cmteh-v2-search-20261112 --port 3162 refresh
```

Остановка только своего экземпляра без удаления данных:

```text
python opencart/dev/v2-local.py --runtime-dir D:/codex/temp/cmteh-v2-search-20261112 --port 3162 stop
```

## Проверки

```text
python opencart/dev/v2-check.py --runtime-dir D:/codex/temp/cmteh-v2-search-20261112 --port 3162
```

Это затронутый локальный checkset: ownership safety, настоящее HTTP-rendering/API, существующие catalog/warehouse/quote PHP/MySQL suites, неизменность исходников и точных файлов default V1 extension archive. Он не заменяет строгий production verifier, host acceptance или recovery. После CSS/Twig fix для узкой повторной проверки есть `--http-only`; это явно не повтор всего набора. Визуальную проверку 1440/1024/390px и пользовательские сценарии выполняет лид в браузере владельца, не в отдельном Playwright browser.

## Устройство

### Каталог: одна панель с вкладками

Выбранный владельцем вариант1: под «Каталогом» открывается компактная панель480px с вкладками «Категории / Бренды». Все прежние динамические ссылки, «Все товары», «Все бренды», parent markers и отдельная ссылка брендов в header сохранены. Панель появляется через CSS до первого paint за280ms; выделение и высота меняются за300ms, предыдущий список затухает160ms, новый проявляется220ms без бокового сдвига и задержки; без bounce и масштабирования текста. Keyboard/reduced-motion переключает сразу. Общий storefront по-прежнему закрывает native details по Escape/внешнему pointerdown и согласует его с hamburger menu.

V2-only `catalog-menu.mjs` подключён на всех V2-страницах; installer копирует один дополнительный asset. ARIA tabs с roving tabindex поддерживают Left/Right/Home/End; Tab ведёт к ссылкам активной группы. До успешного JS-init видны обе группы со всеми ссылками, а неработающие вкладки скрыты. По завершении/cancel удаляется временная высота; resize/keyboard/close/navigation завершают анимацию. На телефоне панель привязана к кнопке через explicit absolute positioning вместо унаследованного fixed, области нажатия44px. Принцип референса: https://21st.dev/@unlumen/components/motion-navigation-menu ; demo source не копировался. Приёмка: `.autopilot/v2-catalog-tabs-2026-11-16.md`. Исправление вспышки от отложенного toggle и покадровая проверка: `.autopilot/v2-catalog-motion-fix-2026-11-16.md`.

Правое меню общей навигации также использует появление280ms через тот же CSS keyframe до первого paint. В V2 отключены конфликтующие inherited opacity/transform transitions. Pointerdown заранее включает motion class; клавиатура/resize снимают его, reduced-motion отключает анимацию через media query. Общий storefront продолжает управлять всеми10 ссылками, focus/Escape/outside и взаимным закрытием двух меню. Сценарий принят в owner browser на native888 и390px: opacity0→0.423→0.786→…→1, keyboard opening animation:none, внешнее нажатие закрывает; checked также `/delivery`. Affected checkset5 safety/28 HTTP/API/assets/127 exact default package unchanged, JS syntax/diff PASS; backend/reference Next.js не перезапускались.

### Карточка — выбранный вариант 5

Владелец выбрал `D:/codex/CMTEH.RU/design-concepts/product-card-variants-2026-11-16/05-catalogue-sheet.png`. V2 product template собирает информацию в каталожный лист без внешней рамки: галерея слева, описание/характеристики по центру, существующие условия покупки справа; коды/файлы и компактные связанные позиции ниже. Все значения — из OpenCart view model, общие ui/cart helpers и data-атрибуты сохранены. Для inventory-managed товара доступны только кнопки конкретных складских предложений; универсальная кнопка из графического эскиза не добавлялась. Полное описание, все характеристики, типы связей, цены и исходные ссылки доступны; длинные данные увеличивают лист, не обрезаются ради высоты макета. Телефон перестраивает эти же данные в узкий поток.

История раскрытия и замеров описана в отчётах PR31–34. На десктопе карточка, поиск и меню сразу занимают конечное положение. Если ответ сервера задерживается, статус загрузки отображается поверх страницы.

### Бесшовный поиск и карточка — 2026-11-16

Выбранный владельцем вариант 1: переходы между главной, выдачей `/catalog`, карточками `/product/...` и `/parts-list` подгружают существующий HTML OpenCart без перезагрузки документа. Одна живая строка поиска перемещается между главной и верхним блоком; header/footer и спокойный фон остаются общей оболочкой. Карточка сохраняет серверные фотографии, характеристики, связи и предложения складов. Обычные прямые ссылки и перезагрузка адреса работают штатно. Корзина `/request` использует ту же оболочку и при повторном открытии заново проверяет цены и складские предложения. У старых ссылок импорта сохранён обычный переход.

«Проценить список или файл» открывает существующую форму в текущем документе. Один живой экземпляр формы сохраняется в скрытом inert-контейнере при уходе с неё: текст, выбранный файл, результаты и выполняющиеся запросы не теряются при возврате в пределах документа, даже после вытеснения записи из кэша истории. Прямое и динамическое открытия используют один общий модуль `parts-list.mjs` и один обработчик на экземпляр формы. API, draft/request keys, валидация и отправка исходного файла остаются общими. Ссылка `/parts-list?article=…` открывает эту же форму и подставляет артикул в нетронутое поле. Ссылка восстановления с параметром `release` выполняет полную загрузку. После полной перезагрузки файл, как прежде, нужно выбрать заново. Приёмка: `.autopilot/v2-seamless-parts-list-2026-11-16.md`.

`navigation.mjs` обновляет адрес, title/canonical/OG/JSON-LD, управляет отменой запросов, фокусом и историей query/scroll. В памяти до 12 живых представлений; лёгкое состояние истории позволяет восстановить более старые. Товар при возврате запрашивается заново для актуальных предложений складов. `view-controls.mjs` подключает только новые элементы карточки/выдачи, импортируя существующие `cart.mjs` и его правила выбора предложения. Исходный default extension не меняется. На десктопе переход с главной и обратно анимирует поиск и заголовок до 320 мс. Внутренние страницы и фильтры сразу занимают окончательное положение. Для узких экранов и сенсорного указателя длительность короткой анимации 250 мс. Клавиатурная навигация и настройка уменьшения движения используют мгновенный переход. Ошибка сети сохраняет текущую страницу и обычную ссылку повторного открытия.

Исправление 2026-11-16: «Найти», Enter и повтор недавнего запроса при единственном результате сразу открывают эту же V2-карточку, включая поиск из раскрытого списка/файла. Решение принимает полный серверный результат каталога (`total == 1`, одна позиция, `partial == false`), а не ограниченные подсказки. Промежуточный каталог не показывается и не добавляется в историю. Ноль/несколько результатов, пустой запрос и явная команда «Показать все результаты» сохраняют выдачу/фильтры каталога. Сценарии и фактические проверки: `.autopilot/v2-search-single-result-fix-2026-11-16.md`.

Приёмка и подтверждённая узкая проверка после одного review: `.autopilot/v2-seamless-product-2026-11-16.md`. Сетевые race/failure и синтетическая галерея проверялись через одноразовый loopback proxy, передающий настоящий V2 HTML; этот proxy не является частью приложения.

Фон главной обновлён 2026-11-16: подробный экскаватор в три четверти, ковш боком и зубьями к кабине. Базовая opacity0.095 на компьютере и0.065 на телефоне сохранена. По выбору владельца параллакс заменён мягким проявлением деталей по принципу Torch Reveal: неподвижный второй экземпляр того же WebP локально усиливает линии через радиальную mask220px, добавочная opacity0.12, fade300ms. Имя `parallax.mjs` сохранено для installer/checkset, но смещения и scroll parallax удалены. Нет idle patrol, мерцания и постоянного rAF; курсор плавно меняет только центр маски. Эффект выключен при ширине<=640px, coarse/touch, reduced-motion и неподдерживаемой CSS mask; на интерактивных элементах и при уходе/навигации он затухает. Новых зависимостей, настроек, изображений и бизнес-изменений нет. Приёмка: `.autopilot/v2-excavator-detail-reveal-2026-11-16.md`.

После синхронизации проверены 5 ownership safety tests, 24 HTTP/API/assets checks, существующие `admin-catalog-integration.php` и `catalog-integration.php`. Default archive совпадает с актуальными исходниками по всем 127 файлам; SHA-256 `bcc029517fa3419682f2ca9cd1d6b6a0692085a44d6ad64213edf8e407933ac4`. Прежний 126-file archive относится к старой базе. Новый head regression прошёл после воспроизведения отсутствующего verification meta до правки. Rendered body и все CSS сохранили прежние SHA-256; прежняя визуальная приёмка остаётся применима. Подробности: `D:/codex/temp/cmteh-v2-search-20261112/evidence/v2-head-sync.json`.

Исходный `opencart/extension/cmteh` не меняется. Launcher устанавливает стандартный архив в отдельный локальный OpenCart, затем копирует эти templates в его `storefront/v2`, assets — в `assets/v2-search`, а runtime `layout.twig` становится тонким include V2. Все рабочие страницы и бизнес-JS берутся из стандартного extension. Обычный production installer не включает эту папку и не переключает V1.

Изображения и их происхождение: `assets-sources.md`. Контакты, название компании, навигация и доступные бренды читаются из прежних моделей; CMS-логотип бренда имеет приоритет над локальным файлом. Незнакомый бренд выводится с текстовым fallback. Asset map описывает лишь представление логотипов, не ассортимент.

Ссылки из статей на загрузку списка открывают форму «Проценить список или файл». Контакты, сортировка и фильтры каталога используют общую навигацию V2. Форма контактов сохраняет введённые данные между переходами в пределах открытой страницы.
