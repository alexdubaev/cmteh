# Склады — текущие границы

Прямое решение пользователя: «Да нам нужны склады, остальное оставим на будущее». Прежние R01–R42 отложены, текущий G01 — склады. Предыдущие вопросы о коммерческой покупке и CRM больше не блокируют этот выпуск.

Новый раунд вопросов отправлен: источник остатков (ручная админка / существующая 1С / файл), публичный показ (только статус / общий доступный остаток / по складам), необходимость ручных резервов. Рекомендации не приняты автоматически; ответов пока нет. Имена/адреса реальных складов должны задаваться владельцем через интерфейс, не выдумываться разработчиком.

Исходные технические факты из warehouse discovery: native quantity — один общий остаток; location — текст, localisation/location — адреса филиалов. Stock по warehouse отсутствует. Native editProduct всегда пишет quantity из формы; открытая до складской операции форма может затереть агрегат. Обновление CMTEH после native save через отдельную PDO не предотвращает эту гонку. Требуется scoped same-native-connection адаптер с блокировкой и проверяемой транзакционной границей. Удаление managed товара должно сохранять историю и проходить через явную защиту, архивирование остаётся. Не расширять защиту на все native действия без необходимости.

Переход: старый общий остаток не объявляется остатком выдуманного физического склада. Пока товар не переведён явным распределением, legacy qty/availability сохраняются. Перевод должен проверять актуальный legacy qty/version и не допускать двойного подсчёта. Решение о публичном показе и резервах ожидается.

Продуктовый код, миграции и хостинг в этом проходе пока не менялись. Проверки приложения не выполнялись, так как есть только discovery и записи Autopilot.


## Обновление: публичные предложения

Владелец явно выбрал публичный показ складов, отдельные цены и зависимые от склада сроки. Прежняя рекомендация скрывать склад/числа не принята и не является требованием. G03–G06 добавлены; выбранное предложение должно быть отдельной позицией корзины/RFQ, не сливаясь только по артикулу. Данные из примера не публиковать автоматически. Точные пути storefront/cart/snapshot исследует warehouse-offers-scout, backend — warehouse-scout.

Новый актуальный раунд вопросов: ручные данные vs1С vsфайл; срок вручную по складу/позиции vsрасчёт по городу; ручные резервы сейчас vsпозже. На момент записи ответов нет. Вопрос о публичном показе закрыт прямыми словами владельца и больше не задаётся. Коммерческий заказ/онлайноплата и аккаунты не возвращены в объём.
