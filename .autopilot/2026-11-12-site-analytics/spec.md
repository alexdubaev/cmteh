# Аналитика и подтверждение прав
## Задача
Владелец должен сам подключать счётчики и метатеги через общую админку.
## Решение
R01: В существующей форме Настройки сайта отдельная явно подписанная группа «Аналитика и подтверждение прав», четыре поля и короткие русские подсказки с форматом, сохранение существующей кнопкой.
R02: Номер Яндекс Метрики. Валидный положительный цифровой ID подключает официальный async tag.js и init на страницах витрины; без Webvisor, отслеживания форм и дополнительных целей.
R03: Идентификатор измерения GA4 формата G-… подключает официальный async gtag.js и config на страницах витрины.
R04/R05: В head витрины корректные yandex-verification и google-site-verification с отдельным кодом content, не целым HTML.
Все поля необязательные. Отсутствующее/пустое поле ничего не подключает; очистка отключает. Валидация на сервере до записи, неверное значение даёт понятную русскую ошибку, не портит предыдущие настройки. Повторное чтение проверяет значения: невалидный legacy/import контент не выводится. Не добавлять свободную вставку HTML/JS, URL скриптов заданы кодом. Коды выводятся с HTML escaping; ID передаются в JS через безопасные атрибуты, а не raw JS.
Сохраняются прежние контакты, карта, меню, настройки и ACL. У админки/API никаких счётчиков. Внешние сбои не мешают витрине.
## Границы
R06: Одна site CMS, один backend и общий layout: V1 и выбранное оформление V2 читают одни и те же четыре ключа из существующего site record и используют текущую админку; отдельный backend/реестр настроек для V2 не создаётся. Эта задача добавляет общую возможность в канонический backend; перенос визуальных файлов V2 и переключение его runtime остаются отдельной задачей. V2 сейчас локальный самостоятельный visual checkout: этот run не меняет его файлы/runtime и не публикует V2; общий интерфейс полей описать для дальнейшего подключения выбранного оформления без второй админки.
## Проверка
Реальная запись/перечитывание/очистка, валидные и опасные/невалидные значения с атомарным отказом и сохранением других полей. Native admin UI и публичный head, условная загрузка скриптов проверяются в локальном браузере с перехватом провайдеров, без настоящих аналитических событий. Одна независимая проверка изменения и чистый клон для приёмки.
## Вне рамок
Конверсионные события, GTM, произвольные скрипты, новые баннеры/consent-система, создание аккаунтов и счётчиков, DNS/файловое подтверждение и автоматическое подтверждение в кабинетах. Прочие старые замечания складов не включены.
## Открытые места
Реальные значения владелец заполнит самостоятельно; сейчас все четыре пусты. Приём аналитики реальными кабинетами не обещается без этих значений.
