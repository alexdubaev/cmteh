# Границы, решённые в спецификации

Все исходники новой версии живут в opencart/. Структура готового расширения в opencart/extension/cmteh/: install.json, admin/controller, admin/view/template, catalog/controller, catalog/view/template, catalog/view/assets, system. OpenCart регистрирует единую тему/модуль и main dispatch; настоящее ядро берётся из официального ZIP. Штатные data/ACL не обходим. Next.js checkout и старый CMS только для сравнения.

- Platform (таск 01) владеет opencart/packaging, opencart/dev, opencart/bin/verify*, install.json, admin/controller/module/cmteh.php, catalog/controller/storefront/router.php, system/Storefront.php, system/Database.php. Тонкий controller отправляет основной запрос в Storefront; пути case-sensitive, не доверяет QUERY route, защищает PHP и private files. Подключает файлы компонентов явно. Главный шаблон extension/cmteh/storefront/layout.twig, данные page/params/model/site/navigation/meta/jsonLd/content/status как описано ниже. Database::connectFromOpenCart(): PDO (MYSQL, native prepares) использует штатные DB_* constants; не обходит ACL. Bootstrap вызывает Catalog::migrate и Lead::migrate для PDO и DB_PREFIX. Shared private files path CMTEH_PRIVATE_DIR (или выделенная директория внутри DIR_STORAGE вне docroot). CMTEH_SITE_URL — конфиг HTTPS origin; локально допускается loopback http.
- Catalog (таск 02) владеет system/Catalog.php и собственными helper classes, bin/import*, bin/generate*, fixtures, admin/controller/module/cmteh_catalog.php + views, tests/catalog*. Namespace Cmteh; Catalog::__construct(PDO $pdo,string $prefix,int $languageId=1,int $storeId=0,?string $privateDir=null). migrate(): void; products(array $query): array returns products,total,page,limit,partial; product(string $slug): ?array; brands(): array; categories(): array; content(string $type, ?string $slug=null, int $page=1): ?array (site/home/navigation/page/article/articles); routes(string $path): ?array for approved legacy redirects or 410 (target/status); sitemap(int $offset,int $limit): array and indexableCount(): int; asset(string $uuid): ?array (absolute verified path/mime/filename). Exact payload uses lib/types.ts shapes with PHP arrays, snake_case fields matching reference, category and brand view metadata as needed. Public getters fail closed. Incoming media stores never public by path. Reuse Catalog for server search and SEO.
- Storefront and RFQ client (таск 03) owns catalog/view/**, local frontend build if needed, browser scenarios tests/browser*. Twig layout consumes page enum home/catalog/brands/brand/category/product/articles/article/page/request/not_found/error, params (normalized GET), model (query-specific data; may include product/products/brands/categories/entries/total/page/limit/content), site, navigation, meta (title, description, canonical, robots, image), jsonLd (preencoded safe JSON) and assets base /extension/cmteh/catalog/view/assets/. Public URLs from reference. /api/search q+mode returns reference shape. /api/lead uses exact brief payload, POST JSON, 200 with id/replayed or error JSON. Site and navigation values are optional, nulls must render gracefully.
- Leads (таск 04) owns system/Lead.php + own helpers, bin/send-leads*, admin/controller/module/cmteh_leads.php + views, tests/lead*. Namespace Cmteh; Lead::__construct(PDO $pdo,string $prefix), migrate(): void; submit(string $raw, string $clientAddress, array $headers=[]): array returns status (int), body (array), optional headers. Read bounded raw request in platform (512001 bytes) and route only POST; pass CONTENT_TYPE and Origin values as normalized lower-case keys. Same-origin checks use configured origin (not Host) in platform. The lead interface does not trust prices. CLI reads private SMTP config via env/secure file, intercept on test transport. Browser credentials never exposed.
- Shared admin ACL access routes extension/cmteh/module/cmteh_catalog and extension/cmteh/module/cmteh_leads; OpenCart login and user_token required; operator/manager permissions distinct. Group setup/permissions and named scripts documented in package. No raw DB connection configuration in Git.
- Composition, SEO, packaging and actual gate are owned by platform; test fixture and test CLI runners owned in respective surfaces. No ticket edits shared files without lead ruling. Paths for tests should work against the composed HTTP server and explicit isolated DB, no ambient credentials or remote targets. Cases requiring a real host or data remain externally gated, not stubs claiming PASS.

## Распределение платформы на установку, маршрутизацию и выпуск

- Таск 01: только общий фундамент — неизменённое ядро, ZIP, безопасная обвязка, Docker PHP/MySQL, install.json, Module, DB/конфиг и контроллер-заготовка. Тонкий маршрут должен принимать основной трафик, разрешать только отдельный документированный локальный smoke до появления Twig/Catalog/Lead и уметь зарегистрировать зависимости через явные require_once. Не ставить заглушки в production: при неготовых зависимостях локальный статус 503; в production вообще не разворачивать частичный пакет. Штатная админка и ACL; каталог/заявки добавляют свои контроллеры. CSS/JS сборка при необходимости локально.
- Таск 05: заменяет только system/Storefront.php, расширяет HTTP проверку, привязывает реальный Catalog/Lead и Twig, реализует URL/SEO, медиа и JSON-LD. Не меняет контракты 02–04 без согласования.
- Таск 06: полный локальный gate, проверка чистой установки, воспроизводимый кандидат и документация REG.RU/rollback/внешние гейты. Только локальная инфраструктура; не делает публикацию и нагрузку на REG.RU без подтверждённого аккаунта и окна.
- Как запускать: ожидается Docker Compose в opencart/dev и documented opencart/bin/verify-local (точный интерфейс добавит 01); основной suite проходит на собранном пакете, доп. тесты запускаются по подсистемам из opencart/tests. Запрещены чужие среды, внешние сообщения, реальные данные, новые GitHub Actions, правки Next.js эталона, платные зависимости. Не выносить секреты, заявки и runtime-артефакты в Git.
