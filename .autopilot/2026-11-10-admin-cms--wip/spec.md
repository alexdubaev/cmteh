# Спецификация: русская админка СМ ТЕХНО

## Задача
Владелец управляет действующей витриной OpenCart через русское меню и формы, без Extensions, JSON и ручной БД. Существующие ID, данные, URL, права и заявки сохраняются.

## Решение
1. Прямое меню «СМ ТЕХНО»: Главная, Товары, Категории, Бренды, Страницы, Главная страница, Статьи, Меню и подвал, Заявки, Настройки сайта. Каталог имеет понятные переходы между штатной формой OpenCart и дополнительными полями СМ ТЕХНО. Нативные экраны создания/редактирования остаются доступны.
2. Русификация используемых штатных экранов, сообщений, фильтров, редактора и выбора изображений через собственные словари расширения, без стороннего языкового пакета, изменения языка данных, прав, сессий или ядра.
3. Формы каталога заменяют дополнительные JSON-поля: выбор бренда, основной и дополнительных категорий, родителя, изображений, характеристик, связанных товаров/документов/кодов; статус, порядок, SEO. SKU/MPN остаются строками. Существующие дополнительные поля сохраняются на сервере при редактировании. Списки с названиями, статусом, поиском и фильтром публикации.
4. Главная: включение и порядок существующих блоков, автоматический или ручной выбор опубликованных брендов/категорий, настраиваемый лимит категорий, отдельное явное включение вложенных. Содержимое, изображения, подписи и ссылки редактируются формами. Значения по умолчанию сохраняют существующую композицию, а лимит 8 становится настройкой.
5. Страницы и статьи: существующие и новые, WYSIWYG, ссылки/картинки, разделы/порядок, черновик/публикация, дата и SEO в одной форме. Предпросмотр опубликованной записи ведёт на её URL; черновик можно просматривать только внутри авторизованной админки, без выдачи публичного токена и без обхода приватности. Системные страницы и их поля доступны в списке. Публичная выдача и sitemap исключают черновики/архив.
6. Меню/подвал: выбор страницы/категории/бренда из списка либо отдельное поле внешнего URL, подпись/область/порядок/статус. Настройки содержат единые контакты, реквизиты, логотип и соцссылки для всех привязанных мест.
7. Сохранение имени не меняет slug. Явная смена адреса требует подтверждения, проверяет коллизии и создаёт 301 со старого пути непосредственно на новый; существующие входящие 301 обновляются без цепочек/циклов. Зарезервированные маршруты и действующие чужие/legacy адреса не перехватываются. SEO: slug, title, description, indexable, canonical для применимых сущностей, в том числе брендов.
8. Скрытие обратимо; физическое удаление только по явному действию с предупреждением. Связанные категории/бренды блокируются до снятия зависимостей. Системные home/site/служебные страницы не удаляются. Удаление отдельного тестового объекта очищает индекс/связи и приводит к явному 404/410, без перевода всех адресов на главную; действующие записи при обновлении не удаляются. Штатные удаления синхронизируются с витриной. Старые релевантные StoreLand 301, canonical и sitemap сохраняются.

## Сценарии и границы качества
- Пустой поиск показывает понятное сообщение и создание новой записи; фильтры и пагинация сохраняются в переходах.
- Некорректный URL, циклический родитель, отсутствующая связь, слишком большой ввод, конфликт URL и неподтверждённая смена адреса дают русскую ошибку; введённые значения остаются в форме. Небезопасный HTML/URL не выполняется. Скрытые технические поля не принимаются через произвольный клиентский JSON.
- Каждый POST проверяет вход, user_token и modify нужного маршрута; GET проверяет access. Видимость меню соответствует серверным правам. Менеджер заявок не видит каталог; оператор каталога не получает установки, управления пользователями или заявками. Доступ к filemanager проверяется отдельно. Не расширять роли автоматически.
- Сохранение имеющихся товаров сохраняет несколько категорий, native-поля, изображения, атрибуты, необслуживаемые поля и импортированные metadata. Нативные правки и импортированные записи используют одну идентичность без дублей. Обновление данных отражается в поисковом индексе.
- Админка не выдумывает цены/остатки/тексты. Приёмочные данные явно синтетические и изолированы. Штатные Cameras/Components не удаляются и не выдаются за ассортимент СМ ТЕХНО.

## Приёмка
Все 8 сценариев раздела 6 ТЗ обязательны: rename/restore существующей категории и бренда без смены URL; создание опубликованных бренда, корневой и вложенной категории и показ главной в выбранном режиме; товар с 000… SKU/MPN, фото и ценой по запросу, штатная правка и поиск; hide/republish/delete только собственных записей; перестановка блока, контакты, draft→publish страницы, выбор её в меню; роли/access/modify/token/анонимность/приватные файлы/filemanager; сохранность данных при upgrade, rollback на отдельной копии и legacy SEO; реальные MySQL-интеграции и короткие браузерные сценарии.

Проверки выполняются по фактической витрине и хранилищу после перезагрузки, не по одному HTTP 200. Полный строгий локальный gate `python opencart/bin/verify-local` сохраняется. Новая поведенческая интеграция и короткий браузерный сценарий дополняют существующие проверки, без тестов исходного текста и постоянной матрицы снимков.

Отдельная совместимость MySQL 5.7 проверяется на выделенном локальном окружении с настоящим MySQL 5.7, отдельно от MySQL 8. Доступ к закрытому REG.RU — read-only для карты данных при наличии готового авторизованного подключения; никаких паролей в чате/Git/логах. Отсутствие доступа фиксируется конкретно, без выдуманной приёмки. Карта каждого типа данных и редактирования и результаты localhost/REG.RU/production различаются.

## Решения по реализации
OpenCart 4.1.0.4, PHP 8.3, MySQL 5.7/8, существующее расширение/Twig/Bootstrap/CKEditor; новые зависимости не требуются. Расширение регистрирует штатные events, не переписывает ядро. Оригинальные русские словари используют совместимые ключи закреплённого OpenCart, происхождение/лицензия и обновление документированы. Язык интерфейса отделён от config_language_id.

Карта данных и маршрут владельца — opencart/admin-guide.md; инструкции обновления/отката — существующая документация с точными дополнениями. Использовать готовый Docker build/cache и upstream ZIP; изолировать runtime/БД.

## Границы и швы
См. interfaces.md. Таск 01 задаёт API каталога/главной; затем формы и навигация работают в разных файлах. Новые поля технические и не требуют ручного JSON.

## Вне рамок
Production/DNS/StoreLand/engine.cmteh.ru, реальный импорт и персональные данные, настройка SMTP/доставка и нагрузочная приёмка не выполняются. Ограничения тестового стенда и реальные данные сохраняются; deploy на закрытый test.cmteh.ru возможен только с актуальными полномочиями, подтверждённой процедурой backup/restore и проверенным кандидатом. Git commit/push/PR/merge разрешены действующими прямыми правилами владельца. Непройденная внешняя проверка остаётся NOT RUN, а не DONE.

## Открытые места
Внешний доступ REG.RU и возможность безопасной проверки/обновления выясняются без запроса секретов. Не считать локальный MySQL 5.7 доказательством работы на конкретном хостинге. Нагрузка, SMTP и реальный каталог непроверены до фактического подтверждения.
