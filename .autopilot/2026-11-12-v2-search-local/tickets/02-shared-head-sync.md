## Что должно заработать

V2 получает настройки общей админки из уже принятого PR26 при сохранении согласованного визуала. В ней нет отдельной реализации счётчиков, новых полей или собственной валидации: только то же подключение существующего head contract, что в актуальной V1 layout. Счётчики local preview остаются выключенными. V1 не изменяется этим таском.

## Из брифа, дословно

> «опираться на существующий функционал саты, а не выдумывать или убирать существующие функции»
> «админка она будет одна для v1 v2, потому что они будут идентичны, разница будет только визуальная»

## Разделы спецификации

Одна админка — G14; Синхронизация общей админки — D01; Вне рамок. Interfaces/notes текущего прогона.

## Критерии приёмки

- [ ] V2 layout потребляет уже принятые analytics/verification данные с той же безопасной семантикой, что актуальная default layout. Новых admin/API/schema/business changes нет; diff относительно origin/main ограничен V2 zone.
- [ ] Existing relevant admin/catalog integration и узкий HTTP head regression PASS; local default счётчики выключены, не отправлены реальные данные наружу. Установленный archive соответствует актуальному default source, новый hash/count записан честно.
- [ ] Body/CSS и выбранный визуал T01 сохранены; если body менялся — требуется новая соответствующая browser capture. Root G4 проверяет final source; прежний126filepackage не выдаётся за текущий.
