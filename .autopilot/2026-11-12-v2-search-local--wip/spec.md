# Спецификация: V2 — локальная поисковая версия

## Задача

«Продолжай собирать V2 с согласованной поисковой главной, запусти локально и покажи, что получилось. V1 не трогай.» Клиенту нужен спокойный интерфейс поиска запчастей и очевидный путь отправки списка, с сохранением существующего функционала.

## Решение

Отдельный локальный экземпляр действующего OpenCart-приложения с презентационным слоем V2. Главная следует выбранному изображению; остальные страницы работают через прежние контроллеры, данные и JS, с общей спокойной шапкой, подвалом и типографикой. Пользователь получает открытый локальный адрес в своём браузере и скриншот результата.

Предыдущие просьбы о трёх вариантах и графических макетах нескольких страниц уже выполнены в предшествующей части диалога. Пользователь выбрал и уточнил вариант «Чистый поиск», а последним указанием поручил продолжить именно его реализацию. Они не отменены молча и не требуют повторной генерации: финальный board содержит главную, результат поиска и список запчастей. Покажем эти три работающих страницы V2 и встроим скриншот в итоговый ответ, а не только сохраним его на диске.

Refero и Awwwards исследованы через браузер на этапе вариантов. Конкретный browser capture `refero-search-home.jpg` в указанной в reference.md папке подтверждает композицию вокруг единственного поиска; Awwwards использован для оценки типографики и интервалов. Более поздний выбранный пользователем макет сильнее общих референсов. Технические условия из AGENTS.md (реальный OpenCart, безопасность отдельной среды, сохранение контрактов, responsive проверки) — ограничения исполнения, не добавленные бизнес-возможности.

## Решения по реализации

- Реальное приложение OpenCart 4.1.0.4, существующий PHP/MySQL runtime. Корневой Next.js не запускается как замена.
- V2 — самостоятельный презентационный overlay вне production extension: Twig/CSS/изображения плюс локальный launcher. Он устанавливается только в собственный disposable runtime. Базовые контроллеры, JS, схемы, API и данные не переписываются; обычный пакет V1 остаётся прежним. Overlay не включается от HTTP-параметра и не публикуется на хост.
- Одна действующая строка поиска с сохранением DOM selectors и ARIA; переиспользовать действующие шаблоны рабочих страниц, включая диалог быстрой заявки. Для главной меняется композиция, не функции.
- Фирменный логотип из source; брендовые логотипы — исходные/официальные файлы с записанным происхождением, без нарисованных словесных подделок. Название и ссылка каждого бренда берутся из существующего view model; для неизвестного бренда текстовый fallback.
- Для рисунка экскаватора использовать отдельный созданный asset в стиле утверждённого макета, не скриншот страницы. Качество проверить визуально.
- Локальные тестовые товары и складские предложения из существующих fixtures, отдельный runtime вне checkout; не копировать настоящую БД, секреты, заявки и private media V1. Никаких внешних уведомлений.
- Проверки соразмерны затронутому: старт/повторный старт, существующие HTTP/интеграционные проверки поиска/корзины/списка и складских предложений; targeted визуальная проверка 1440/1024/390. Проверить неизменность packaged V1 extension относительно origin/main. Полный host/recovery gate не объявлять выполненным; серверный релиз не входит в задачу.

## Одна админка — уточнение G14

V1 и V2 различаются только презентацией. Для V2 не создаётся отдельная управляемая админка, новые редакторы, бизнес-правила или схема контента: оба оформления совместимы с существующими CMS/view models. Пользователь сначала смотрит локальный визуал и выбирает оформление, после чего отдельным шагом выбранный presentation layer подключается к существующей системе управления. Сейчас разрешён только локальный preview; реальная БД/админка V1 не подключается и не изменяется. Native OpenCart в disposable local runtime — тестовая инфраструктура существующего приложения, не второй продукт, который владельцу нужно наполнять и вести.

Приёмка G14: в репозитории только новые presentation assets/local preview tools; не добавлены admin controllers/editors/schema/API, README объясняет один backend/admin и порядок выбора визуала. Данные для видимых компонентов берутся из тех же моделей, что и V1.
